# 追踪策略运行过程

**追踪（tracing）** 是 qteasy 提供的一项调试功能：在策略的 ``realize()`` 方法中插入追踪点，把运行过程中的中间变量记录下来，回测结束后以 ``DataFrame`` 的形式一并查看。它解决的是「策略算出来的信号我看不懂、不知道是哪一步算错」的问题。

> **注意**：追踪**不是**一种运行模式，而是回测过程中的一个可选功能，由配置项 ``trace_log`` 控制（默认值 ``True``）。配置项 ``mode`` 的说明文本中出现了「3 / trace 追踪模式」的写法，但 ``qt.run()`` 的实际分派是 ``mode=3`` 进入统计预测、``mode=4`` 直接报 ``ValueError: Invalid run mode: 4``。因此要启用追踪请使用 ``trace_log``，不要试图用 ``mode`` 进入「追踪模式」。

## 工作原理

一次回测中，追踪数据按下面的链路产生：

1. 回测启动时，若 ``trace_log`` 为 ``True``，``Backtester`` 调用 ``op.enable_tracing()``，为 Operator 中每个策略分配长度为「信号总行数」的存储空间；
2. 每运行一个时间步，Operator 调用 ``update_trace_step(step)`` 把写指针推进到当前行；
3. 策略在 ``realize()`` 里调用 ``self.trace(name, var)``，把变量值写入当前行；
4. 回测结束后，``Backtester.trace_result_df`` 把各策略的追踪数据按列拼接，行索引取 Operator 的信号索引（``op_signal_index``），并并入回测的交易汇总数据。

换句话说，追踪表的**一行对应一条交易信号**，**一列对应一个你插桩的变量**。

## 相关接口

| 接口 | 作用 |
|------|------|
| ``Strategy.enable_tracing(max_steps)`` | 启用该策略的追踪，预分配 ``max_steps`` 行空间 |
| ``Strategy.disable_tracing()`` | 关闭追踪并清空已记录的数据 |
| ``Strategy.update_trace_step(step)`` | 把写指针推进到第 ``step`` 行（回测中由 Operator 自动调用） |
| ``Strategy.trace(name, var)`` | 在当前行记录一个变量，``name`` 为变量名、``var`` 为变量值 |
| ``Strategy.get_trace_data()`` | 以 ``DataFrame`` 形式返回该策略已记录的全部追踪数据 |
| ``Operator.enable_tracing()`` / ``disable_tracing()`` | 对 Operator 内所有策略统一启用 / 关闭追踪（回测中由 ``Backtester`` 自动调用） |
| ``Backtester.trace_result_df`` | 回测结束后全部策略的追踪数据，行索引为信号索引 |
| ``qt.QT_CONFIG['trace_log']`` | 全局配置项，是否启用追踪，默认 ``True`` |

## 可追踪的变量类型

``trace()`` 只接受 **int、float、bool、str** 四类值（含对应的 numpy 标量类型）。传入其他类型会直接报错：

```text
TypeError: When trace variables, only int, float, bool, str types are supported, got <class 'list'> instead!
```

``enable_tracing()`` 的 ``max_steps`` 必须是正数：

```text
ValueError: max_steps should be a positive integer, got 0(<class 'int'>) instead
```

## 在 realize() 中插桩

下面是一段插桩写法示例。``self.trace()`` 的三行分别记录了一个浮点数、一个布尔值和一条字符串备注：

```python
import qteasy as qt
from qteasy import RuleIterator, Parameter


class TracedDMA(RuleIterator):
    def __init__(self):
        super().__init__(
            name='traced_dma',
            pars=[Parameter((5, 20), name='s', value=12),
                  Parameter((20, 60), name='l', value=26)],
            data_types='close_E_d',
            window_length=60,
        )

    def realize(self):
        close = self.get_data('close')
        p = self.get_pars()
        short = close[-p['s']:].mean()
        long_ = close[-p['l']:].mean()

        self.trace('short_ma', float(short))
        self.trace('long_ma', float(long_))
        self.trace('bull', bool(short > long_))

        return 1.0 if short > long_ else 0.0
```

> **本章待补**：上述策略在**完整回测**中取出追踪表的端到端示例（含 ``Backtester.trace_result_df`` 的真实输出）尚未补齐——撰写本章时本机数据源中缺少该示例所需的 ``close_E_d`` 历史数据，无法跑通并截取真实结果，为避免给出臆造输出而留空。补齐时需要一份可用的本地数据源。

## 追踪数据的结构（可运行示例）

追踪表的列名格式为 ``{策略ID}_{变量名}``，一行对应一个追踪步骤。下面这段示例不需要数据源，可独立运行：

```python
import qteasy as qt

op = qt.Operator(strategies='dma', signal_type='pt')
stg = op.strategies[0]

stg.enable_tracing(max_steps=5)
for i in range(5):
    stg.update_trace_step(i)
    stg.trace('short_ma', 10.0 + i)
    stg.trace('bull', bool(i % 2 == 0))
    stg.trace('note', f'step-{i}')

print(stg.get_trace_data())
```

```text
   dma_short_ma  dma_bull dma_note
0          10.0         1   step-0
1          11.0         0   step-1
2          12.0         1   step-2
3          13.0         0   step-3
4          14.0         1   step-4
```

调用 ``disable_tracing()`` 会关闭追踪并清空数据，之后 ``get_trace_data()`` 返回空表：

```python
stg.disable_tracing()
print(stg.get_trace_data())
```

```text
Empty DataFrame
Columns: []
Index: []
```

## 已知限制

- **``FactorSorter`` 与 ``GeneralStg`` 暂未适配**：这两个基类的 ``realize()`` 通常返回向量（一次覆盖多只股票），而 ``trace()`` 只能记录单个标量。源码中对此留有 TODO，当前版本不要依赖这两个基类的追踪输出。
- **追踪只在启用时生效**：``trace()`` 在未启用追踪时是静默的空操作，不会写入任何数据，也不会报错。调试时若发现追踪表是空的，先确认 ``trace_log`` 配置项是否为 ``True``。
- **追踪会带来额外开销**：每个追踪变量都要预分配一整列并逐步写入，变量多、信号行数多时会增加内存与运行时间。
