# Group 与策略信号混合

一个 Operator 中的多个策略，按 ``run_freq``（运行频率）与 ``run_timing``（运行时机）被划分为若干个 **Group（策略组）**：频率与时机相同的策略归入同一组，在同一时刻一起运行；每个 Group 再用 **blender（混合器表达式）** 把组内多个策略的信号合并成一个。当 Operator 内不止一个 Group 时，组与组之间的合并方式由 ``group_merge_type`` 决定。

## 交易信号的三种类型

每个 Group 都有一个 ``signal_type``，它决定了组内信号数字的含义。``signal_type`` 只能取 ``'pt'``、``'ps'``、``'vs'`` 三者之一（大小写不敏感，框架内部统一转为小写）：

| 取值 | 全称 | 信号数字的含义 |
|------|------|----------------|
| ``'pt'`` | position target | 目标持仓权重 |
| ``'ps'`` | proportional signal | 相对总资产的买卖比例 |
| ``'vs'`` | value / volume signal | 固定金额或固定数量的买卖指令 |

```python
import qteasy as qt

op = qt.Operator(strategies='dma, macd', signal_type='pt')
print([g.signal_type for g in op.groups.values()])
```

```text
['pt']
```

（两个策略的运行频率与时机相同，归入同一个组，因此这里只有一个组。）

传入非法取值会直接报错：

```python
qt.Operator(strategies='dma', signal_type='xx')
```

```text
ValueError: signal_type should be one of ["pt", "ps", "vs"], got xx instead
```

## Group 的由来

- 创建 Operator 或调用 ``add_strategy()`` 时给定的 ``run_freq`` / ``run_timing``，决定策略被分到哪个组：与已有某组相同则并入该组，否则新建一组。
- 运行频率与时机相同的策略同组、同时运行；频率或时机不同则分属不同组，各自按自己的时间表运行。

```python
import qteasy as qt

op = qt.Operator(signal_type='pt')
op.add_strategy('dma', run_freq='d', run_timing='open')
op.add_strategy('macd', run_freq='d', run_timing='close')

for g in op.groups.values():
    print(str(g))
```

```text
Group_1@d/open:['dma']
Group_2@d/close:['macd']
```

## 查看 Group 与 blender

| 接口 | 返回内容 |
|------|----------|
| ``op.groups`` | 所有策略组组成的字典，键为组名、值为 ``Group`` 对象 |
| ``op.get_blender(group_name=None)`` | 各组的混合器（前缀表达式形式）；指定组名时只返回该组 |
| ``op.view_blender(group=None)`` | 混合器的可读形式，把 ``s0`` 等下标替换成策略 ID |
| ``Group.member_strategy_ids`` | 该组成员策略的 ID 列表 |
| ``Group.strategy_count`` | 该组的策略数量 |
| ``Group.human_blender`` | 该组混合器的可读字符串 |

```python
import qteasy as qt

op = qt.Operator(strategies='dma, macd', signal_type='pt')
print(op.get_blender())
print(op.view_blender())
```

```text
{'Group_1': ['*', 's1', 's0']}
{'Group_1': 'dma * macd'}
```

## blender 表达式

### 默认 blender

不指定 blender 时，``Group`` 按 ``signal_type`` 与成员数量自动生成默认表达式：

- ``'pt'``：所有信号**相乘**，如两个策略时为 ``s0*s1``；
- ``'ps'`` / ``'vs'``：所有信号**相加**，如两个策略时为 ``s0+s1``。

```python
import numpy as np
import qteasy as qt
from qteasy.group import Group

g_pt = Group('g', signal_type='pt')
g_pt.add_strategy(qt.get_built_in_strategy('dma'))
g_pt.add_strategy(qt.get_built_in_strategy('macd'))
print(g_pt.blender_str, '->', g_pt.blend([np.array([0.5]), np.array([0.8])]))

g_ps = Group('g', signal_type='ps')
g_ps.add_strategy(qt.get_built_in_strategy('dma'))
g_ps.add_strategy(qt.get_built_in_strategy('macd'))
print(g_ps.blender_str, '->', g_ps.blend([np.array([0.5]), np.array([0.8])]))
```

```text
s0*s1 -> [0.4]
s0+s1 -> [1.3]
```

> 可以这样理解两者的差别：把同组策略想象成几个同时发言的参谋——``pt`` 默认相乘，任一参谋给出 0 仓位就会把整体仓位压到 0，表决偏向「一票否决」；``ps`` / ``vs`` 默认相加，各位参谋的买卖意见会累加起来。这只是帮助理解的比方，实际计算就是上面两个表达式的字面含义。

### 自定义 blender

用 ``op.set_blender(blender, group_id=None)`` 设置。``blender`` 可以是字符串、字符串列表或字典；``group_id`` 为 ``None`` 时作用于全部策略组。

```python
import qteasy as qt

op = qt.Operator(strategies='dma, macd', signal_type='pt')
op.set_blender('0.5*s0 + 0.5*s1')
print(op.view_blender())
```

```text
{'Group_1': '0.5 * dma + 0.5 * macd'}
```

表达式中 ``s0``、``s1``、``s2`` … 依次对应该组内的第 1、2、3 … 个策略（按加入顺序）。可用运算符与优先级由 ``blender_parser`` 定义：

| 运算符 | 优先级 | 说明 |
|--------|--------|------|
| ``^`` | 2（最高） | 幂 |
| ``*`` ``/`` | 1 | 乘、除 |
| ``&`` ``and`` | 1 | 逻辑与 |
| ``~`` ``not`` | 1 | 取反 |
| ``+`` ``-`` | 0 | 加、减 |
| ``\|`` ``or`` | 0 | 逻辑或 |

可用括号 ``(`` ``)`` 强制优先计算。常用写法：

| 表达式 | 含义 |
|--------|------|
| ``s0`` | 只取第一个策略的信号 |
| ``s0*s1`` | 两信号逐元素相乘（``pt`` 的默认行为） |
| ``0.5*s0+0.5*s1`` | 两信号等权平均 |
| ``(s0+s1)/2`` | 与 ``0.5*s0+0.5*s1`` 等价 |
| ``s0+s1`` | 两信号相加（``ps`` / ``vs`` 的默认行为） |

设置时框架会用 ``blender_parser`` 解析表达式，无法解析的表达式在赋值给 ``Group.blender_str`` 时会抛出 ``ValueError``。

## 多个 Group 之间的合并：group_merge_type

当 Operator 里存在多个 Group，且它们在同一时间点都产生信号时，``group_merge_type`` 决定这些组信号如何合并。构造 Operator 时通过关键字参数传入，合法取值为 ``'none'``、``'and'``、``'or'``（大小写不敏感），**默认为** ``'None'``：

```python
import qteasy as qt

for v in ['none', 'and', 'or']:
    op = qt.Operator(strategies='dma', group_merge_type=v)
    print(f'input={v!r} -> stored={op.group_merge_type!r}')

qt.Operator(strategies='dma', group_merge_type='xor')
```

```text
input='none' -> stored='None'
input='and' -> stored='And'
input='or' -> stored='Or'
ValueError: Invalid group_merge_type (xor)
```

三种取值的实际行为（依据 ``Operator.run_strategy()`` 的实现）：

| 取值 | 行为 | 合并初始值 |
|------|------|-----------|
| ``'None'`` | 各组信号**独立执行**，每个组各产生一条信号，互不合并 | 不适用 |
| ``'Or'`` | 各组信号**相加**后合并为一条信号 | ``0`` |
| ``'And'`` | 各组信号**相乘**后合并为一条信号 | ``1`` |

也就是说，``'Or'`` 的合并结果是 ``0 + 组1信号 + 组2信号 + …``，``'And'`` 的合并结果是 ``1 × 组1信号 × 组2信号 × …``。对于取值为 0 / 1 的多空信号，相乘相当于「与」、相加相当于「或」，这便是两个名字的来历。

需要注意：``group_merge_type`` 不为 ``'None'`` 时，同一时间点的多个组会被合并成一条信号；此时若这些组的 ``signal_type`` 不一致，框架无法判断以哪一个为准，会抛出 ``RuntimeError``。要么让所有组使用相同的 ``signal_type``，要么保持 ``group_merge_type='None'``。

## 运行前检查

``op.is_ready()``（或等价的属性写法 ``op.ready``）检查 Operator 是否已具备生成交易信号的最小条件。``tell_me_why=True`` 会打印不满足的具体原因：

```python
import qteasy as qt

op = qt.Operator(strategies='dma, macd', signal_type='pt')
print(op.is_ready(tell_me_why=True))
```

```text
Operator readiness:  Not Ready
Strategy (dma) share info not set -- share_count or share_names not set!
Strategy (macd) share info not set -- share_count or share_names not set!
No data buffer -- data buffers are empty!
No data window -- data window views are not created!
No data indices -- data window indices are not set!
No group timing table -- group timing table is not created!
No group running schedule -- group schedules are not set!

False
```

上述缺失项（股票池、数据缓冲区、运行时间表等）由回测 / 实盘流程在运行前自动补齐，因此这里返回 ``False`` 是正常的，不代表配置有误。
